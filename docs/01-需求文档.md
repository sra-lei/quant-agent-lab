# 01 · 需求文档（PRD）

> 版本 v0.1 ｜ 状态：待评审 ｜ 日期 2026-11-13

## 1. 背景与问题

单人做 A 股投研，真实的痛点不是"拿不到数据"——行情、财报、公告都能查到。痛点在流程侧：

| 问题 | 具体表现 | 后果 |
|---|---|---|
| 标准漂移 | 今天按估值买、明天按情绪追，没有固定判据 | 事后无法归因，错在哪说不清 |
| 无法回溯 | 三个月的分析散落在聊天记录、笔记、截图里 | 同样的坑反复踩 |
| 视角单一 | 一个人不可能同时客观地做价值与情绪两套判断 | 结论被最近一次情绪左右 |
| 复盘缺失 | 只记"对了的"，错的自动遗忘 | 系统不进化 |

## 2. 目标与非目标

### 2.1 目标

1. **把投研流程固化为可重复执行的流水线**：给定目标 → 自动取数 → 多视角分析 → 汇总结论 → 落库 → 次日复盘
2. **让每个结论都可追溯**：谁（哪个 Agent）、基于什么数据、在什么时点、给出什么判断
3. **形成闭环反馈**：观察员对历史结论打分，评分回灌给规划官调整权重（v0.3）
4. **开源可用**：任何人 clone 下来，无付费账号也能用 Mock 数据跑通全链路

### 2.2 非目标（明确不做）

- ❌ **不接券商交易接口，不自动下单**（合规 + 责任边界）
- ❌ 不做实时高频交易（本项目是日线级别研究）
- ❌ 不做行情软件替代（不追求 Tick 级低延迟）
- ❌ v1 不做组合优化/风险模型（后续评估）

## 3. 用户与场景

### 3.1 主要用户

- **个人量化/主观投资者**（首要）：有自己的交易体系，需要一套自动化助理
- **投研学习者**：想理解多 Agent 如何协作完成一次完整研究

### 3.2 核心场景

**场景 A：每日盘后研究**
```
16:00 触发
→ 信息收集员同步当日行情/资金/公告
→ 价投专家输出「基本面视角候选 + 理由」
→ 游资专家输出「情绪视角候选 + 理由」
→ 规划官合并、去重、按风险预算分配关注度
→ 观察员记录本次结论快照（用于未来打分）
```

**场景 B：单票深研**
```
用户输入：600519 贵州茅台，关注点=估值是否合理
→ 收集员拉近 8 季财报 + 近 60 日行情 + 近 90 天公告/研报
→ 价投专家：DCF/相对估值两路交叉
→ 游资专家：近期资金与情绪面（作为反向参考）
→ 规划官：合并成一份带分歧标注的结论
```

**场景 C：周度复盘**
```
周日 20:00
→ 观察员读取本周全部结论快照
→ 用真实行情回算：命中率、平均收益、最大回撤
→ 归因：错在数据、逻辑还是执行
→ 输出周报 + 给规划官的权重调整建议
```

## 4. 功能需求

### 4.1 Agent 能力（P0）

| ID | 需求 | 验收标准 |
|---|---|---|
| A-01 | 财务规划官：接收目标，产出任务计划 | 计划包含：任务列表、依赖顺序、每个任务的输入契约；可被编排器执行 |
| A-02 | 财务规划官：合并多专家结论 | 输出含分歧标注（两个专家结论冲突时必须显式指出，不得静默取平均） |
| A-03 | 信息收集员：拉取并清洗数据 | 输出符合 `MarketSnapshot` 契约；含数据时间戳与来源；缺失字段显式标 `null` 而非 0 |
| A-04 | 信息收集员：入库幂等 | 同一交易日重复执行不产生重复记录 |
| A-05 | 价投专家：输出基本面候选 | 每个候选必须含：估值方法、关键假设、证伪条件 |
| A-06 | 游资专家：输出情绪面候选 | 每个候选必须含：驱动逻辑、情绪阶段（启动/发酵/退潮）、失效条件 |
| A-07 | 观察员：生成复盘报告 | 含命中率、归因、可执行改进项；不可只写"表现良好"这类空话 |

### 4.2 编排与运行时（P0）

| ID | 需求 | 验收标准 |
|---|---|---|
| O-01 | 可替换编排层 | `Orchestrator` 接口有两个实现：Simple（自研状态机）、LangGraph；切换只改配置 |
| O-02 | 运行可观测 | 每次运行有 run_id，记录每个 Agent 的输入摘要、输出、耗时、token 消耗 |
| O-03 | 失败可恢复 | 单个 Agent 失败不阻塞全局；失败记录原因，可单独重跑该节点 |
| O-04 | 成本可控 | 单次日度运行 token 成本有上限配置，超限中止并告警 |

### 4.3 前端（P0）

| ID | 需求 | 验收标准 |
|---|---|---|
| F-01 | 总览页 | 展示最近运行状态、今日候选、市场概览 |
| F-02 | 策略管理 | 增删改查策略（名称、类型、参数、启用状态） |
| F-03 | 信号列表 | 按日期/标的/来源 Agent 筛选；可点进详情看完整推理链 |
| F-04 | 运行轨迹 | 以时间线展示一次 run 中每个 Agent 的输入输出 |
| F-05 | 复盘报告 | 周报列表与详情，支持图表（命中率趋势） |
| F-06 | 智能体编辑器 | 新建/编辑智能体：名称、角色描述、工作流、可用工具、输出格式；保存前可试运行 |

### 4.4 数据层（P0）

| ID | 需求 | 验收标准 |
|---|---|---|
| D-01 | 数据源抽象 | 统一 `DataProvider` 接口；新增数据源不改业务代码 |
| D-02 | 多源适配 | 至少实现：Mock（默认）、通达信 MCP、Wind MCP |
| D-03 | 数据质量守卫 | 入库前校验：时间戳新鲜度、字段完整性、异常值（涨跌幅 > 20% 需标记） |

## 5. 非功能需求

| 维度 | 要求 |
|---|---|
| 部署 | 单机可跑；2C2G 云主机或本地 PC；依赖尽量少 |
| 性能 | 日度全流程 < 10 分钟；单票深研 < 3 分钟 |
| 成本 | 日常运行 LLM 成本可控；默认使用低价模型，重要判断可切高价模型 |
| 可维护 | Agent 之间零直接依赖，只通过契约通信 |
| 安全 | API Key 只存环境变量；日志不落密钥；Wind 密钥不上云 |
| 合规 | 输出页面固定展示"不构成投资建议" |

## 6. Agent 职责定义（摘要）

> 完整输入输出契约见 [03-Agent契约.md](03-Agent契约.md)

### 6.1 财务规划官 Planner
- **角色**：投研组长 / PM
- **输入**：目标（关注什么）、资金规模、风险偏好、时间窗
- **输出**：`TaskPlan`（任务 DAG）+ `ResearchConclusion`（合并结论）
- **禁止**：不得直接给买卖建议；只做取舍与合并
- **关键设计**：专家结论冲突时**必须显式标注分歧**，不做平均化处理

### 6.2 信息收集员 Collector
- **角色**：数据工程师
- **输入**：标的池、时间窗、需要的数据类型
- **输出**：`MarketSnapshot`
- **禁止**：不得编造缺失数据；取不到就标 null 并写明原因
- **关键设计**：每条数据带 `source` 与 `as_of`，前端可溯源

### 6.3 价投专家 ValueAnalyst
- **角色**：基本面分析师
- **输入**：`MarketSnapshot` + 策略参数（估值方法、安全边际阈值）
- **输出**：`AnalystView`，含候选、理由、估值区间、证伪条件
- **禁止**：不得使用情绪面指标作为主要依据

### 6.4 游资专家 MomentumAnalyst
- **角色**：短线情绪交易员
- **输入**：`MarketSnapshot` + 策略参数（情绪阶段、资金强度阈值）
- **输出**：`AnalystView`，含候选、驱动逻辑、情绪阶段、失效条件
- **禁止**：不得混淆"情绪强"与"基本面好"

### 6.5 观察员 Reviewer
- **角色**：复盘官 / 风控
- **输入**：历史结论快照 + 真实行情
- **输出**：`ReviewReport`（命中率、归因、改进项）
- **禁止**：不得只给结论不给证据；不得评价未来（只看已发生）

## 7. 数据需求

| 数据类别 | 字段示例 | 更新频率 | 来源 |
|---|---|---|---|
| 日线行情 | 开高低收、量、额、换手 | 每日 | 通达信 |
| 基本面 | 营收、净利、ROE、现金流、PE/PB 分位 | 季度 | Wind |
| 资金面 | 主力净流入、龙虎榜 | 每日 | 通达信 |
| 情绪面 | 涨停家数、连板高度、炸板率 | 每日 | 通达信 |
| 公告研报 | 标题、类型、摘要 | 每日 | 通达信 MCP |
| 宏观 | CPI、PMI、社融 | 月度 | Wind |

## 8. 风险与约束

| 风险 | 影响 | 对策 |
|---|---|---|
| LLM 幻觉（编造数据） | 结论不可信 | 所有数字必须来自 `MarketSnapshot`，Agent 不得自造；契约层做字段校验 |
| 数据源限流/失效 | 流程中断 | 多源 + 缓存 + 降级到 Mock 并显式标注 |
| 推理成本失控 | 费用高 | 单次运行 token 上限；分级模型路由 |
| 过拟合策略 | 回测好看实盘亏 | 强制样本外验证；观察员按时间滚动评分 |
| 合规风险 | 责任边界 | 不接交易接口；页面固定免责声明 |

## 10. 总览大屏（FR-10）

**定位**：一屏回答「什么阶段 / 钱往哪走 / 我该做什么」，不是数据罗列。
完整设计见 [`09-总览大屏设计.md`](./09-总览大屏设计.md)。

| 编号 | 模块 | 核心内容 | 数据来源 | 当前状态 |
|---|---|---|---|---|
| FR-10.1 | 全景态势图 | 战略要览、市场阶段、综合情绪指数、核心矛盾 | `agent:planner` + zvt | 占位 |
| FR-10.2 | 资金博弈图 | 板块净流入/流出前五 | akshare 板块资金流 | 占位 |
| FR-10.3 | 情绪脉搏图 | 60 日情绪指数曲线 + 极端区标的 | zvt（已可算） | 占位 |
| FR-10.4 | 机会雷达图 | 五轴风格强度 + 推荐方向 | zvt + `agent:strategy` | 占位 |
| FR-10.5 | 风险预警列表 | 核心矛盾与风险点，按级别排序 | 规则引擎 + `agent:reviewer` | 占位 |
| FR-10.6 | 持仓仪表盘 | 盈亏、热点匹配度、调仓建议 | 手工/CSV（不接券商） | 占位 |

**必须满足**：

- 任一模块缺数据时显示「未接入 / 今日未生成」，**不得显示 0 或空图**
- 每个数字可追溯来源与截止时间
- 红涨绿跌，A 股配色
- 持仓只存本地，系统只给建议不下单
