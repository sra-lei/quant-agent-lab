# 10 · 数据能力矩阵与智能体收敛

> 起因：智能体定义得越来越细（13 个），但数据侧只有 1.5 条管道。
> 本文把「每个工作流步骤需要什么数据 / 现在有没有 / 能不能买到」拉平成一张表，
> 据此决定哪些智能体今天就能跑、哪些要降级、哪些应该先挂起来。

日期：2026-11-13

---

## 0. 一句话结论

**智能体的数量，不该超过数据管道的数量。**

现在的情况是：13 个智能体，1.5 条可用数据管道（日线 + 涨停梯队）。
按"今天能端到端跑出可用结论"的标准，**只有 1 个能跑通**（游资复盘高手，且要降级），
**3 个能跑一半**，**9 个跑不了**。

问题不在于智能体设计得不好，而在于**顺序反了**：
先定义"一个理想的投研团队该干什么"，再去找数据——
而市场和数据源不会配合你的工作流。

---

## 1. 数据分级（L1–L4）

| 级别 | 定义 | 落地成本 | 现在有哪些 |
|---|---|---|---|
| **L1** | 已入库、有工具、可直接查 | 0 | 全市场日线（4424 只 × 450 日）、行业归属、缠论方向/中枢 |
| **L2** | 能用现有数据算出来，但没写成工具 | 半天~1 天/个 | 涨停梯队、连板、炸板、封板率、涨跌家数、情绪指数、指数收益、风格强弱 |
| **L3** | 需要新增采集，接口免费但未接入 | 0.5~1 天/个 | 指数日线、板块行情/成分、涨停池明细（封板时间/封单）、龙虎榜、融资余额、财务摘要、公告标题、板块资金流 |
| **L4** | 拿不到 / 成本极高 / 不稳定 | 周级或不建议做 | 分时逐笔、实时舆情秒级、北向实时净流入、大宗商品产量、产业链零部件出货、政策 60 秒解读 |

**规则：智能体的每一步，只能落在 L1 或 L2；L3 必须先建管道再写智能体；L4 不进工作流。**

## 3. 三类问题的分界

### 3.1 真·数据缺失（要建管道）

- **指数日线**：本地 `index_1d_kdata` 0 行。akshare 可取，1 小时能补 3 年。
- **板块行情与成分**：`block_*` 全 0。akshare 可取，需要建板块维度表。
- **涨停池明细**：已有方案（`stock_zt_pool_em` 实测可用，含首封时间、封单、炸板次数、连板数、换手率、流通市值）。

### 3.2 伪需求（该砍或改）

- **"每小时计算情绪指数"**：日线库没有盘中数据。要么改成"每日收盘后"，要么接入实时行情（成本高、意义有限——情绪指数日内变化本来就不稳定）。
- **"全市场 3 年历史回测"**：历史只有 1.8 年。要么回补到 3 年（可行，一次性 ~1 天），要么把回测窗口改成 1.5 年并明确标注。
- **"北向资金实时净流入"**：2024 年 8 月起交易所已停止实时披露，只剩持股明细。这个字段**不可能拿到**，必须删除，不能降级。

### 3.3 数据"能拿到"不等于"能稳定拿到"

这是今天实测发现的另一个坑，比缺数据更隐蔽：

| 时间 | 接口 | 结果 |
|---|---|---|
| 上午 | `stock_zh_a_spot`（全市场快照） | ✅ 5578 行，17 秒 |
| 中午 | `stock_zt_pool_em`（涨停池） | ✅ 37 行，字段完整 |
| 中午 | `stock_zt_pool_zbgc_em`（炸板池） | ✅ 35 行 |
| 中午 | `stock_lhb_detail_em`（龙虎榜） | ⚠️ 返回空表 |
| 下午 | `stock_individual_fund_flow_rank`（资金流） | ❌ 连接被断 |
| 下午 | `index_zh_a_hist`（指数日线） | ❌ 连接被断 |
| 下午 | `stock_board_industry_name_em`（板块） | ❌ 连续 2 次断连，间隔 45 秒仍失败 |

同一台机器、同一个库，几个小时内从"能取"变成"取不到"，
大概率是**东财对云机 IP 限流**。

**含义**：

- L3 的"0.5~1 天接入"是**接口调研时间**，不含稳定性工程
- 真正上线必须配：请求节流、指数退避重试、失败告警、本地缓存兜底、必要时多源（东财/新浪/腾讯）
- 每天只跑一次的任务，失败要有**补偿窗口**（我们已经在 zvt 同步任务里做了：失败 20 分钟重试）

**结论：数据管道是常驻系统，不是一次性脚本。** 建管道的成本要按"长期维护"估，不是按"写个脚本"估。

### 3.4 能力错配（智能体在该用数据的地方用了大模型）

- **"策略回测"** 用 LLM 生成胜率/回撤 —— 回测是确定性计算，模型只能解释结果，不能产出数字。
- **"情绪指数"** 每个智能体各算一套公式 —— 同一个指标必须只有一个实现，否则两份报告的数字会对不上。

## 4. 建议：收敛到 3 + 1

不要 13 个平推，先做能跑通的，其余冻结。

### 第一优先级（现在就能跑，降级版）

**① 游资复盘高手**
- 可用：连板梯队、封板率、面王、涨跌家数、成交额、涨停池明细（待接）
- 降级：历史比对只覆盖 450 个交易日，且要标注"样本 1.8 年"
- 缺：涨停原因（题材归属），影响"主线判断"

### 第二优先级（补 1 天管道后能跑）

**② 市场状态诊断专家** —— 补指数日线 + 板块行情，就能出"阶段标签"
**③ 市场风格雷达 / 量化策略总监（二选一）** —— 补风格指数后二选一保留

### 第三优先级（要先建数据资产）

**④ 价投专家 / 基金投研助手（二选一）** —— 需财务数据 + 行业估值分位

### 建议冻结

主题投资策略师、产业链感知网络、政策雷达、市场情绪脉搏仪（盘中版）、策略回测
—— 冻结不是删掉，是**把 workflow 写成数据条件未满足时的"待接入"状态**，避免每天跑出空报告。

## 5. 一个隐性问题：智能体 id 与角色错位

你改写过内置智能体的角色，现在 id 和内容对不上了：

| agent_id | 名称 | 问题 |
|---|---|---|
| `reviewer` | 市场状态诊断专家 | id 本意是"观察员/复盘评分" |
| `collector` | 量化策略总监 | id 本意是"信息收集员" |
| `momentum_analyst` | 策略回测 | id 本意是"游资/动量专家" |
| `planner` | 首席投资官 AI | 语义接近，但职责从"调度"变成"写战略要览" |

**影响**：编排层按 id 找智能体（`SimpleOrchestrator` 里写死了 planner → analysts → reviewer 的顺序），
一旦 id 与职责错位，跑出来的链路和名字不符。

**建议**：内置 id 只保留四个语义清晰的槽位——
`planner`（调度/汇总）、`collector`（取数）、`analyst_value`、`analyst_momentum`、`reviewer`（复盘）。
其余全部作为自定义智能体，不参与默认编排。

## 6. 防复发：智能体准入清单

从下一个智能体开始，先过三问，答不上来就不建：

```
1. 这条 workflow 的每一步，具体需要哪些字段？（不是"需要行情"，是"需要涨停股的首次封板时间"）
2. 这个字段现在在哪？L1 工具 / L2 可算 / L3 待采 / L4 拿不到？
3. 如果是 L3：谁去采、多久一次、失败怎么办、上线前几天算"数据可信"？
```

**产品层面的改造（待做）**：

- 编辑器里给每个 workflow step 增加 `data_deps` 字段（声明所需数据）
- 保存时校验：`data_deps` 里出现 L4 的，直接红字拦住
- 试运行时校验：某一步的依赖数据在本次 run 里缺失，就在报告里标注"该步骤未执行（缺 X）"，**不允许模型硬编**
