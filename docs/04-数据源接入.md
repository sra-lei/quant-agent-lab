# 04 · 数据源接入

> 目标：**新增一个数据源，不需要改任何 Agent 代码。**

## 1. 统一抽象

所有数据源实现同一个协议（见 `backend/app/data/base.py`）：

```python
class DataProvider(Protocol):
    name: str
    def health(self) -> ProviderHealth: ...
    def quotes(self, codes, start, end) -> dict[str, list[Bar]]: ...
    def fundamentals(self, codes, period) -> dict[str, Fundamental]: ...
    def announcements(self, codes, days) -> list[Announcement]: ...
    def market_breadth(self, on) -> MarketBreadth: ...
```

汇总为一次 `MarketSnapshot` 由 `data/aggregator.py` 完成，任何字段失败都进 `quality.missing_fields`。

## 2. Mock（默认，零依赖）

- 用途：本地开发、CI、开源用户第一次 clone
- 行为：按代码哈希生成确定性伪随机行情，保证同一输入每次结果一致（便于测试）
- 明确标注：`source = "mock"`，前端显示"演示数据"角标

## 3. 通达信 MCP

### 3.1 背景
通达信 2026 年 6 月开放 MCP 数据通道，提供 10 类工具：实时行情、K 线、条件选股、公式选股、公告查询、研报查询、热点资讯、宏观数据、板块主题、股票检索。

### 3.2 接入方式（二选一）

**A. 官方/托管 MCP 服务**
拿到 MCP endpoint + 鉴权方式后，配置：

```env
TDX_MCP_ENDPOINT=https://<your-endpoint>
TDX_MCP_TOKEN=<token>
```

**B. 自建（开源方案）**
- `tdx-mcp`（PyPI）：基于通达信公开行情服务器封装 MCP Server
- `eltdx`：通达信行情协议 Python 库，支持快照/分时/逐笔/K线/竞价，可作为 HTTP/WS 服务暴露

自建示例：

```bash
pip install tdx-mcp
tdx-mcp --port 8100          # 暴露 MCP over HTTP
```

```env
TDX_MCP_ENDPOINT=http://127.0.0.1:8100
```

### 3.3 能力映射

| 项目需求 | 通达信工具 |
|---|---|
| `quotes` | 实时行情 / K线数据 |
| `announcements` | 公告查询 / 研报查询 |
| `market_breadth` | 板块主题 / 热点资讯 |
| 选股初筛 | 条件选股 / 公式选股 |

### 3.4 注意
- 公开行情服务器有频率限制，客户端需实现：批量合并、退避重试、本地缓存
- 仅供个人研究，商用需自行取得授权

## 4. Wind MCP

### 4.1 两条路，成本完全不同

| 方式 | 说明 | 成本 |
|---|---|---|
| **AIFin Market 平台** | aifinmarket.wind.com.cn 注册拿 `WIND_API_KEY`，官方 MCP | **单独计费，按积分扣** |
| **本地 WindPy + 自建 MCP** | 用已付费终端额度，开源 `wind-mcp` 封装 | **边际成本 0** ✅ |

**本项目采用 B**：复用已有终端，避免额外计费。

### 4.2 部署要求
- 必须跑在**装有 Wind 终端且已登录的 Windows** 上
- 开源方案：[`abuttoncc/wind-mcp`](https://github.com/abuttoncc/wind-mcp)，基于 FastMCP，暴露 `wind_wsd` / `wind_wss` / `wind_wses` / `wind_tdays` 等工具

```bash
git clone https://github.com/abuttoncc/wind-mcp
pip install -r requirements.txt
python src/wind_mcp_direct_server.py --host 0.0.0.0 --port 8888
```

```env
WIND_MCP_ENDPOINT=http://192.168.1.20:8888   # 本机或内网
```

### 4.3 云端怎么连本机

Wind 密钥不能上云，所以 MCP 只能留在本机。三种做法：

| 方案 | 适合 | 说明 |
|---|---|---|
| 全本地 | 起步阶段 | 后端也跑本机，最简单 |
| 内网直连 | 同一局域网 | 云机不可行 |
| 隧道（frp / cloudflared） | 云端跑、本机供数 | 只放行 MCP 端口，加 IP 白名单 + token |

**安全要求**：隧道只暴露 MCP 端口；`WIND_MCP_TOKEN` 必填；日志不打印密钥。

### 4.4 优先级与冲突
同时挂多个源时，按**字段级**优先级合并，而不是整源覆盖：

```yaml
priority:
  bars:          [tdx_mcp, wind_mcp, mock]
  fundamentals:  [wind_mcp, tdx_mcp, mock]
  announcements: [tdx_mcp, wind_mcp, mock]
```

理由：通达信行情更实时，Wind 财务口径更权威。合并结果在 `snapshot.source` 里记录为 `composite(tdx_mcp,wind_mcp)`。

## 5. 数据质量守卫（DataGuard）

任何源的数据入库前必须过四道校验：

| 校验 | 规则 | 失败处理 |
|---|---|---|
| 新鲜度 | `as_of` 落后 > 1 个交易日 | `stale=true`，下游必须标注 |
| 完整性 | 关键字段缺失 | 置 `null` + 记入 `missing_fields` |
| 异常值 | 单日涨跌幅 > 20%（非 ST/新股） | `anomaly=true`，限制 conviction |
| 一致性 | 同日多源收盘价偏差 > 1% | 记录冲突，取优先级高的源 |

## 6. 缓存策略

```
内存 LRU（单次运行内） → SQLite（跨运行，按 as_of 分片） → 远端
```

- 行情：按交易日落盘，永不重复拉取历史
- 基本面：按 `report_period` 缓存，季度更新
- 公告：按日增量，保留 90 天

## 7. 新增数据源的步骤

1. 在 `backend/app/data/` 新建 `xxx_provider.py`，实现 `DataProvider`
2. 在 `data/registry.py` 注册
3. 在 `.env` 加连接配置
4. 加一条 `tests/test_provider_xxx.py`（用固定快照断言，不打真实网络）

**不需要改 Agent、不需要改编排、不需要改前端。**

## 8. 通达信问小达（已接入，实测）

通达信的 Key **分类型**，不同类型解锁的能力完全不同。用户申请的是**问答词元**，
它只暴露一个自然语言工具 `tdx_wenda_quotes`（`question` + `range` + `page/size`），
不是那套 `tdx_quotes` / `tdx_kline` / `tdx_screener` 结构化工具。

```
DATA_PROVIDER=tdx_wenda
TDX_MCP_ENDPOINT=https://mcp.tdx.com.cn:3001/mcp
TDX_MCP_TOKEN=TDX-********
```

### 8.1 协议要点

- 走 **MCP Streamable HTTP**：`initialize` → `notifications/initialized` → `tools/list` / `tools/call`
- 服务端以 **SSE** 返回（`event: message\ndata: {...}`），必须解析 `data:` 行
- 需要回传 `Mcp-Session-Id`
- 鉴权头是 `tdx-api-key`，`TDX-` 和 `TDX:` 两种前缀都能通
- 密集调用会返回 `WENDA_HTTP_ERROR: 服务暂时繁忙` → 需要**节流 + 退避重试**

实现见 `data/mcp_streamable.py`（协议层）和 `data/tdx_wenda.py`（业务适配）。

### 8.2 能力边界（2026-11-13 实测）

| 需求 | 状态 | 说明 |
|---|---|---|
| 收盘价序列 | ✅ | 单次最多 **20 个交易日**，超过返回空表 |
| 成交量序列 | ✅ | 同上，偶尔繁忙 |
| 市盈TTM / PB / ROE / 营收同比 | ✅ | 一次问句全拿到 |
| 涨停家数 | ✅ | 取返回体 `meta.total`（返回的是清单，长度即家数） |
| 净利同比 | ❌ | 该词元不返回 |
| 涨跌家数 | ❌ | 换个问法会被理解成别的语义 |
| 公告 | ❌ | 问公告仍返回行情行；直接抛错，不返回空列表冒充"没有公告" |
| 20 日以上历史 | ❌ | 需结构化 key 或本地库 |

### 8.3 设计取舍

**拿不到的就是拿不到。** 契约里 `Bar.open/high/low`、`MarketBreadth.advancers`
全部改成 `Optional`，缺数据就留 `None` 并计入 `missing_fields`；
量能、市场温度这些维度在缺数据时**直接不计分**并写 warning，
而不是用 0 顶上去——0 会被下游当成"量能极小""全市场无涨停"。

代价是：一个 3 只股票的 run 大约消耗 7 次问句，且高峰期偶发繁忙重试，
单次 run 可能需要 1–2 分钟。

## 9. 本地 zvt 库（已接入，工具可自选）

云端跑过 zvt 全量同步，全市场日线 + 缠论因子都在本地 sqlite 里，
所以「历史数据」和「情绪结构」这块走本地库，不花词元、不受接口限流。

```
ZVT_DATA_DIR=~/zvt-home/data      # 默认值，可覆盖
```

| 文件 | 表 | 规模 |
|---|---|---|
| `em/em_stock_1d_hfq_kdata.db` | `stock_1d_hfq_kdata` | 4424 只 × 2025-01-02~2026-11-12，196 万行 |
| `em/em_stock_meta.db` | `stock` / `stock_industry` | 4424 只，5222 条行业映射 |
| `zvt/zvt_stock_1d_zen_factor.db` | `stock_1d_zen_factor` | 177 万行，含方向/笔/中枢 |

**只读打开**：`sqlite:///...?mode=ro`。这些库是每日同步任务在写的，
应用侧绝不写、不加排他锁。

### 9.1 三个工具

| 工具 | 参数 | 返回 |
|---|---|---|
| `zvt.kline` | `code`, `days` | 日线（尾部 12 根）+ 缠论最新状态（方向/笔/中枢上沿下沿） |
| `zvt.limit_board` | `date?` | 涨停清单（含连板数、行业、成交额）、梯队分布、炸板数、封板成功率、面王、涨跌家数 |
| `zvt.breadth` | `date?` | 涨跌家数、涨跌停数、中位涨幅、成交额、最高连板 |

`date` 缺省取库内**最新交易日**；传了会自动对齐到 ≤ 它的最近交易日。

### 9.2 口径（自己算的，不依赖 zvt 的标记位）

实测 `is_limit_up` / `change_pct` / `turnover_rate` 这几个字段在 hfq 表里**全是 0**，
所以全部按收盘价推算：

- **涨跌停比例**：主板 10%、创业板(30)/科创板(688) 20%、北交所(8/4/920) 30%、ST 5%
- **涨停判定**：`close / prev_close - 1 >= 比例 - 0.004`（分位取整的容差）
- **连板**：从当日往前逐日套同一判定，遇到断板即停
- **炸板**：盘中最高价摸到涨停价，但收盘未封住
- **封板成功率**：涨停数 /（涨停数 + 炸板数）
- **面王**：当日最高价 ≥ 昨收 +5% 的股票里，收盘回撤 (high-close)/high 最大的那只

### 9.3 实测（2026-11-12）

```
涨停 37 | 跌停 6 | 炸板 42 | 封板率 46.8% | 最高 5 板
梯队：5板2 4板2 3板2 2板5 1板26
涨跌：上涨 656 / 下跌 3668 / 平 97，中位 -1.57%，成交 1.6 万亿
面王：华阳智能(301502) 回撤 17.56%
```

前一日 11-11 是 82 家涨停、上涨 2796 家 —— 两天情绪反转，正好是复盘要抓的点。

### 9.4 与问小达的分工

| 需求 | 用哪个 |
|---|---|
| 全市场历史日线、连板梯队、炸板、涨跌家数 | `zvt.*`（本地，免费、无限流） |
| 当日实时报价、PE/PB/ROE、公告 | `market.*`（问小达） |

Agent 编辑器里两类工具可以**同时勾选**，模型自己决定调哪个。

### 9.5 每日增量同步（cron）

本地库只到 11-12，要每天复盘就得有人把当天的日线灌进去。定时任务已经挂上：

```cron
30 15 * * 1-5 /home/ubuntu/zvt-home/sync_daily.sh >> /home/ubuntu/zvt-home/logs/cron.log 2>&1
```

脚本：`deploy/zvt-sync/sync_daily.sh`（线上副本在 `~/zvt-home/sync_daily.sh`）

- **15:30 跑**：收盘 15:00 后留半小时给数据源落库
- **自动重试一次**：跑完检查当日行数，为 0（数据源延迟或休市）就等 20 分钟再跑一遍
- **日志**：`~/zvt-home/logs/zvt-sync-YYYY-MM.log`，超过 5MB 自动归档
- **体检**：`~/zvt-home/sync_daily.sh --check` 只查库状态和当日行数，不写库

底层仍是 `~/zvt-home/incremental_sync.py`：从 akshare 拉全市场日线，
`INSERT OR REPLACE` 进 zvt 的 sqlite（幂等，重复跑不会产生脏行）。

**已知口径**：该脚本拉的是 `adjust="qfq"`，但表名是 `hfq`，且每天只追加当日一行——
实际等价于「每日真实价」。对当日涨跌幅判断没影响，唯独除权日会出现一次假的巨阴/巨阳，
统计层面属于噪声。要彻底干净得改成拉不复权后自行累计复权因子。

**缠论因子（`zvt.kline` 里的 zen 字段）不会自动更新**：现有 zen 计算脚本是
「扫一批股票再算」的一次性脚本，不是增量任务。要做日更需要单独改造。
